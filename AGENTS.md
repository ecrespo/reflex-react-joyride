# AGENTS.md

This repository is a Python package that wraps
[react-joyride](https://react-joyride.com) as a Reflex component. The package
lives in `src/reflex_react_joyride/`; `demo/` is a Reflex app for trying it.
The layout follows Reflex's official
[component template](https://github.com/reflex-dev/component-template).

## Commands

| Task | Command |
|---|---|
| Install | `uv sync` |
| Lint, format, type-check | `uv run pre-commit run --all-files` |
| Test | `uv run pytest` |
| Regenerate the `.pyi` stub | `cd src && uv run python -m reflex_base.utils.pyi_generator reflex_react_joyride && rm -rf assets` |
| Build (generates `.pyi` stubs) | `rm -rf dist && uv build` |
| Run the demo | `cd demo && uv run reflex run` |
| Check the demo compiles | `cd demo && uv run reflex compile` |

Run the lint and test commands before every commit.

## How the component is built

- `joyride.py` defines `Joyride`, an `rx.NoSSRComponent` (react-joyride
  touches `window`). Its `library` is not the npm package directly but the
  local wrapper `joyride_tour.jsx`, shipped as a package asset, which calls
  react-joyride's `useJoyride` hook; react-joyride itself is pinned through
  `lib_dependencies` to `JOYRIDE_VERSION` in `constants.py`.
- Do not name a module `component.py`, `app.py` or any other name in
  `EXCLUDED_FILES` in `reflex_base.utils.pyi_generator`: the stub generator
  skips those files silently.
- Props are `rx.Var[...]` class attributes. Reflex sends snake_case names to
  React as camelCase. Structured props (`Step`, `TourOptions`, `Locale`,
  `TourStyles`, `FloatingOptions`) are `rx.PropsBase` classes in `props.py`;
  give every field a `= None` default so type checkers accept partial
  construction.
- Events are `rx.EventHandler[spec]` attributes; every trigger receives the
  flat `JoyrideEvent` payload from `events.py`.
- `actions.py` holds the Python-side controls (`start`, `next_step`, ...),
  which call into the wrapper through the tour id.
- Export every public name from `__init__.py`.
- After changing the JSX wrapper or `library`/`tag`, load the demo in a
  browser: a broken import can compile and only fail at render.

Reference: https://reflex.dev/docs/wrapping-react/overview/

## Stubs

`.pyi` files are generated by the `hatch-reflex-pyi` build hook during
`uv build` (and on the first `uv sync`) so editors see each prop as a keyword
argument. They are git-ignored; do not write them by hand. The hook skips
generation when it already built the same version, so regenerate the stub with
the command above after changing props.

## Tests

Tests live in `tests/` and check what the component imports and how it renders
(`str(component)` is the generated JSX). Add a test for each new prop or event.

## Releasing

Versions come from git tags (`uv-dynamic-versioning`); there is no version in
`pyproject.toml`. Merge `develop` into `main`, then push a tag `vX.Y.Z` on
`main`: `.github/workflows/release.yml` tests, builds and publishes to PyPI
through trusted publishing. Do not rename that workflow file or its `pypi`
environment, PyPI's trusted publisher is bound to them.
